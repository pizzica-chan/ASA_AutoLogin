このツールについて

ASA_Login は、接続先サーバーをあらかじめ選択した状態から、 JOIN ボタンのクリック〜ログイン待ち〜失敗時の復帰までを自動で繰り返すツールです。

ツールが行うこと
  • サーバー一覧の JOIN →（必要なら）MODS の JOIN → ログイン待ち
  • 満員などで失敗したときの Enter 確定・BACK / JOIN GAME による復帰と再試行
  • タイトル画面での NETWORK FAILURE 処理（Enter → Space → JOIN GAME）
  • （任意）Discord への終了通知・停滞通知
ツールが行わないこと
  • SESSION NAME によるサーバー検索
  • Official / Unofficial などのサーバータブ切り替え
  • サーバー行の選択（ユーザーが手動で選択してください）

インストールと起動

配布版（Python 不要・推奨）

  1. ASA_Login-win64.zip を任意のフォルダに展開します。
  2. ASA_Login.exe をダブルクリックして起動します。
  3. 初回起動時に config.yaml と templates/ が自動作成されます。

展開後のフォルダ構成の例:

ASA_Login/
  ASA_Login.exe
  config.example.yaml
  config.yaml          … 初回起動で自動生成
  templates/           … 画面キャプチャ（セットアップで作成）
  templates/buttons/   … ボタン認識用 PNG
  logs/                … ログファイル
  使い方.txt

開発版（Python あり）

pip install -r requirements.txt
python gui.py

クイックスタート

  1. ARK を起動し、マルチプレイのサーバー一覧を表示します。
  2. 接続したいサーバーの行をクリックしてオレンジ色で選択します。
  3. ASA_Login の 「セットアップ」 を押し、最小モード（推奨） で ① サーバー一覧を登録します。
  4. ARK を表示しているモニターを GUI の 「ARK を表示しているモニター」 で選びます。
  5. 「キャプチャ範囲」 は通常 「ゲームウィンドウ」（推奨）のままで問題ありません。
  6. 「開始」 を押し、確認ダイアログの指示どおりの状態であることを確認して実行します。
最小セットアップのポイント
① サーバー一覧のキャプチャだけで、非 MODS サーバーなら基本的に動作します。
画像優先モードでは、エラーダイアログは同梱ボタン PNG や画面テンプレートで検出し、③-A / ⑥ は Enter キーで確定します。エラー画面をわざと起こす必要はありません。
MODS サーバーでは、② のキャプチャまたは join_mods 座標の登録を推奨します。

自動化の流れ（①〜⑦）

1 回の接続試行は ① → ②（任意）→ ③ です。失敗した場合は復帰ルートに入り、再び ① から繰り返します。

① サーバー一覧（選択済み）→ 右下 JOIN
        ↓
② REQUIRED MODS（表示された場合のみ）→ 左下 JOIN
        ↓
③ ログイン試行（待機）
   ├─ 成功（ゲーム内画面を検出）→ 完了
   ├─ ③-A CONNECTION FAILED → Enter → ④ BACK → ⑤ JOIN GAME → ①
   └─ ⑥ NETWORK FAILURE → Enter → ⑦ Space → ⑤ JOIN GAME → ①
番号 画面 操作 備考
① サーバー一覧 右下の JOIN をクリック サーバーは事前選択済みであること
② REQUIRED MODS モーダル左下の JOIN 出ないサーバーはスキップ
③ ログイン処理中 待機のみ 成功・失敗・動画のいずれかを監視
③-A CONNECTION FAILED Enter キー（CANCEL 相当・ACCEPT は使わない） サーバー一覧上のダイアログ
④ 空のサーバー一覧 左下の BACK MULTIPLAYER SERVERS: 0 など
⑤ メインメニュー JOIN GAME カードをクリック ④枚 / ⑤枚タイル両対応（レイアウト自動判定なし・2 PNG を試行）
⑥ NETWORK FAILURE Enter キー（ACCEPT 相当） タイトル画面のダイアログ
⑦ タイトル画面 Space キー ⑤ と同様に JOIN GAME へ

⑤ メインメニューの例（④枚タイル）

各操作で使うボタン画像

クリック対象は templates/buttons/ 内の PNG を画面上から検索して押します（座標フォールバックあり）。③-A / ⑥ は Enter キーで確定し、ボタン PNG はダイアログ検出に使います。

リトライ設定

  • 最大試行回数 … 0 のとき成功するまで無制限に繰り返します。
  • リトライ間隔 … 失敗して ① に戻ったあと、次の試行まで待つ秒数です。

セットアップ

GUI の 「セットアップ」 ボタンから、画面キャプチャとクリック座標を登録します。

最小モード（推奨）

① サーバー一覧だけ登録すれば、非 MODS サーバーでは動作します。
画像優先モードでは、復帰用の BACK 等は同梱 PNG で検出します。③-A / ⑥ のダイアログも PNG または画面テンプレートで検出し、Enter で確定します。

個別モード

必要な画面だけチェックボックスで選んで登録します。② MODS だけ追加したい場合などに使います。初期状態ではすべて未チェックです（① も含め、必要な項目だけオンにしてください）。

フルモード

すべての画面を順に登録します。解像度や UI レイアウトが大きく異なる環境向けです。

画像ファイルの役割（3 層）
  • templates/*.png … セットアップで保存した正本（最優先で使用）
  • assets/defaults/fallback_screens/ … 未登録時の実行時フォールバック
  • docs/setup_samples/ … ウィザードの参考表示のみ（認識には不使用）
詳細ログの templates_source: fallback は、自分のキャプチャではなく同梱フォールバックを使っている印です。
ステップ 保存ファイル クリック登録 / 確定
① サーバー一覧 templates/server_list.png 右下 JOIN
② MODS（任意） templates/required_mods.png 左下 JOIN
③-A CONNECTION FAILED templates/connection_failed.png —（Enter キー）
④ 空のサーバー一覧 templates/server_list_empty.png BACK
⑤ メインメニュー templates/main_menu.png JOIN GAME
⑥ NETWORK FAILURE templates/network_failure.png —（Enter キー）
⑦ タイトル画面（任意） templates/title_screen.png —（Space キー）
成功判定（推奨） templates/buttons/login_success.png（右下 HUD） —
成功判定（フォールバック） templates/in_game.png —
再セットアップが必要なタイミング
  • ゲームの解像度や表示モード（ウィンドウ / フルスクリーン）を変更したとき
  • キャプチャ範囲（ゲームウィンドウ ↔ モニター全体）を切り替えたとき
  • モニターの割り当てを変えたとき
  • UI スケールや言語設定を変えたとき
  • セットアップで保存した PNG の色味が実画面と大きく違うとき（古いバージョンで採取した場合など）
環境専用ボタン画像
クリック位置の登録時に、周辺を templates/buttons/captured/ へ 自動切り出しし、元画面で再検出できることを確認します。 生成できない場合は従来どおり同梱ボタン画像と登録座標を使用し、 手動で差し替えたボタン画像は上書きしません。
キャプチャ範囲について
  • ゲームウィンドウ（推奨） … ARK の描画領域（クライアント領域）のみをキャプチャします。ウィンドウモード運用向け。
  • モニター全体 … 選択したモニター全体をキャプチャします。フルスクリーン運用向け。
モード変更後は、座標とテンプレート画像の基準が変わるため、セットアップの再実行を推奨します。
セットアップと設定の保存
セットアップ完了時に config.yaml が更新されます。 GUI に未保存の変更がある場合は、続行前に確認ダイアログが表示され、 現在のフォーム内容も含めて保存されます（意図せず設定が消えることはありません）。

GUI の各タブ

メイン 基本設定

  • 注意事項 … 動作前の確認ポイント
  • ARK を表示しているモニター … サブモニター運用時はここで対象を選択
  • キャプチャ範囲 … 「ゲームウィンドウ」（推奨）または「モニター全体」。変更後はセットアップ再実行を推奨
  • 最大試行回数 / リトライ間隔 … 失敗時の繰り返し設定
  • 診断情報をコピー … 現在のキャプチャ領域、DPI、認識度、推奨対策をクリップボードへコピー
  • 設定を保存 … フォーム内容を config.yaml に書き込み
  • 初期値に戻す … config.example.yaml の初期値に戻して保存（templates/ の画像は削除されません）
開始前診断
「開始」後、ARK ウィンドウ、キャプチャ可否、黒画面、セットアップ時との 解像度・DPI差、サーバー一覧と JOIN ボタンの認識度を確認します。 「開始不可」は修正が必要です。「注意」は理由を確認したうえで続行できます。 解像度・表示倍率・ARK の表示モードを変えた場合は、再セットアップが最も確実です。 診断中は別スレッドで処理するため、GUIは応答を維持します。 診断コピーにはアプリ版、OS、DPI、モニター、テンプレート由来、ログ保存先も含まれます。

待ち時間 場面ごとの待機

①〜⑦ の各場面で、どれくらい待つかを細かく調整できます。読み込みが遅い PC では少し長めにすると安定しやすいです。

項目説明
開始までの待ち「開始」押下後、実際の操作を始めるまでの秒数
画面チェック間隔ボタン・画面状態を確認する間隔（短いほど反応は早い）
クリック前の安定確認回数クリック前に同じ判定を連続何回満たすまで待つか（2 推奨。早押し防止）
クリック前 / 後の待ちボタン検出からクリックまで、およびクリック後の安定待ち
② MODS 画面の確認時間① JOIN 後、MODS が出るかどうか見る時間
③ ログイン結果の待ち成功・失敗・動画のいずれかが出るまでの上限
失敗後の画面復帰待ちEnter 確定・BACK 後の復帰待ち上限

画像認識 一致度の調整

  • 画面判定の一致度 … サーバー一覧やメインメニューなど全体画面の判定
  • ボタン判定の一致度 … JOIN / BACK などボタン画像の判定（③-A / ⑥ 用 PNG はダイアログ検出）
  • ② MODS 画面の一致度 … MODS の出現判定（低めの値がデフォルト）
  • ② MODS 画面の検出 … 検出方式（ハイブリッド推奨）と画面比較範囲（中央モーダル推奨）
  • ② REQUIRED MODS をスキップ … MODS 不要サーバー向け。有効にすると ① の直後に ③ へ進みます
  • ARK ウィンドウのタイトル … 通常は変更不要
  • 操作前に ARK を前面に出す … サブモニター運用ではオン推奨
  • クリック位置を表示 … 通常操作は短い青、失敗復帰は短い橙のリップルで表示

誤クリックが多い → 一致度を上げる。見逃しが多い → 一致度を下げる。

クリック表示は入力を遮りません。排他フルスクリーンではゲームの背面に隠れることがあるため、見えない場合はボーダーレス表示を試すか、詳細ログの「クリック表示」を確認してください。

クリック座標 ％座標とクリック方式

左上 (0, 0)、右下 (100, 100) のパーセント座標で各ボタンの位置を指定します。対象は ① JOIN / ② MODS JOIN / ④ BACK / ⑤ JOIN GAME です（③-A / ⑥ は Enter 確定のため不要）。セットアップで登録した値もここに反映されます。

各行の 「画面で設定」 から、モニター上をクリックして座標を登録できます（キャプチャ範囲の基準に従います）。

クリック方式動作
画像優先 ボタン画像が見つかればその位置をクリック。見つからなければ登録座標
画像のみ 画像が見つからない場合は座標にフォールバックしない
座標優先 登録座標を優先（画像は補助）
座標のみ クリックは ① / ② / ④ / ⑤ の座標。③-A / ⑥ は Enter 確定。到達判定は画面テンプレート＋ボタン PNG（② は mods_detect_mode: hybrid 推奨）

座標プレビュー ボタンで、設定した位置をモニター上に点表示して確認できます。

ログエリア

  • ログ … 進行状況のわかりやすい表示（通常はこちら）
  • 詳細ログ … 類似度・座標など技術情報（原因調査用）

ログファイルは既定で 5MB × 3 世代にローテーションされます。 設定保存は原子的に行われ、直前の正常な設定は config.yaml.bak に残ります。

Discord 通知（任意）

GUI の 「Discord 通知」 タブで、Webhook 経由で Discord チャンネルへメッセージを送れます。 離席中にログイン結果や異常を知りたい場合に使います。

Webhook URL の取得
Discord の対象チャンネル → チャンネル設定 → 連携サービス → Webhook → 新規 Webhook を作成 → URL をコピー

通知が送られるタイミング

タイミング通知
ログイン成功送る
ログイン失敗（リトライ上限など）送る
エラー終了（ウィンドウ喪失など）送る
停止ボタンで停止送らない
開始カウントダウン中に停止送らない
同じフェーズが n 回連続で進まない（停滞通知）送る（下記「停滞通知」参照）

各設定項目

項目説明
Discord 通知を有効にするWebhook URL が設定されているときのみ有効
Webhook URLhttps://discord.com/api/webhooks/... 形式（旧 discordapp.com も可）。他人に見せないでください

停滞通知の例

stuck_repeat_threshold を 10（デフォルト）にすると、次のような状態が 10 回連続したときに通知します（1 回の停滞エピソードにつき 1 通知）。

  • ① サーバー一覧に戻れない
  • ⑥ からの復帰に失敗し続ける
  • ARK を前面にできない / ウィンドウを確認できない

Server full 等で ③-A / ⑥ から正常に復帰できた試行は停滞カウントに含めません。停止ボタンを押したあとの停滞検出も通知しません。

セキュリティ
  • Webhook URL は config.yaml に平文保存されます
  • 詳細ログに設定を出力するとき、Webhook URL は *** にマスクされます
  • 診断情報コピーには Webhook URL は含まれません

config.yaml での設定例

notifications:
  discord:
    enabled: true
    webhook_url: "https://discord.com/api/webhooks/..."
    mention_user_ids: ["123456789012345678"]
    mention_everyone: false
    attach_screenshot: true
    stuck_repeat_threshold: 10

ボタン画像の差し替え

実行時に参照するのは templates/buttons/ 内の PNG です。 初回起動時に assets/defaults/buttons/（配布版では同梱データ）からコピーされます。

  1. ゲーム画面で対象ボタン部分を切り出した PNG を用意します。
  2. templates/buttons/ に同じファイル名で上書き保存します。
  3. ASA_Login を再起動するか、次の試行から反映されます。
主なファイル名
  • join_server_list.png … ① サーバー一覧 JOIN
  • join_mods.png … ② MODS JOIN
  • cancel_failed.png … ③-A ダイアログ検出（Enter で確定）
  • back_empty_list.png … ④ BACK
  • join_game.png … ⑤ JOIN GAME（④枚タイル）
  • join_game_center.png … ⑤ JOIN GAME（⑤枚タイル）
  • accept_network_failure.png … ⑥ ダイアログ検出（Enter で確定）
初回コピー後は既存ファイルを上書きしません。古い PNG が残っている場合は手動で差し替えてください。 ⑤ の JOIN GAME 検出は join_game.png と join_game_center.png を毎回両方試します（④枚 / ⑤枚タイルの自動判定はありません）。 どちらも自分の画面に合わない場合は、該当 PNG を切り出して差し替え、あわせて ui.join_game 座標も再設定してください。

ログの見方

出力先内容
GUI「ログ」タブ 今どの段階か、成功・失敗などユーザー向けメッセージ

古い config.yaml で logging.file のみ指定している場合、詳細ログはそのパス（例: logs/asa_login.log）に出力されます。新形式は user_file / detail_file です。

うまくいかないとき

症状から段階（①〜⑦）を特定し、症状 → 対策マトリクスを参照してください。 多くの場合、セットアップ再実行・一致度調整・待ち時間調整のいずれかで改善します。

最初に確認すること（共通）
  1. サーバー行がオレンジ色で選択されているか
  2. 「ログ」タブでどの段階で止まったか（① JOIN / ② MODS / ③ 待機 / 復帰 など）
  3. 「詳細ログ」で類似度が閾値より高いか低いか
  4. キャプチャ範囲（ゲームウィンドウ / モニター全体）が運用と一致しているか
  5. 解像度・表示モード・モニター変更後はセットアップ再実行済みか
  6. 詳細ログの templates_source に fallback / missing がないか（あればセットアップ追加を検討）
座標のみモードで開始に必要な座標
  • 必須: ① JOIN / ④ BACK / ⑤ JOIN GAME
  • ③-A / ⑥: Enter キーで確定（座標不要）。検出は画面テンプレートまたは templates/buttons/ の PNG
  • MODS サーバー: ② MODS JOIN 座標も登録（未登録だと② をスキップ）
  • 画面キャプチャ（templates/*.png）は ① 必須。他は未登録でもボタン PNG 検出で補える場合あり

一致度調整の基本ルール

  • 見逃しが多い（ボタン/画面が見つからない）→ 一致度を下げる
  • 誤クリック・早押し・別画面判定 → 一致度を上げる、または安定確認回数を 3 に
  • 一度に大きく変えず、0.02〜0.05 刻みで試す
  • 変更後は「設定を保存」→ 再試行

方式うまくいかないときの対処

座標優先 座標を優先しつつ、待機判定に画像を使用。うまくいかない場合は座標の再設定または一致度調整
画像のみ ボタン PNG の精度が必須。座標では救えない

注意事項

  • 接続先サーバーは必ず手動で選択してください（オレンジ色のハイライト）。
  • 操作時に ARK ウィンドウが一瞬前面に出ます（完全なバックグラウンド動作ではありません）。
  • ゲームの利用規約に違反する可能性があります。自己責任でご使用ください。
  • Windows 10 / 11（64bit）向けです。
